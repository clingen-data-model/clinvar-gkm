# Documentation conventions

Docs are MkDocs + Material in `docs/`, deployed to GitHub Pages by `.github/workflows/deploy-docs.yml`.

- Run `mkdocs build --strict` after **any** docs change and fix all warnings before committing (broken links
  and other warnings fail the strict build).
- Use the `write-docs` skill for creating/editing MkDocs pages.

## Terminology

- **GKM (Genomic Knowledge Model)** = the schema set (VRS, Cat-VRS, VA-Spec). **GKS (Genomic Knowledge
  Standards)** = the GA4GH workstream that curates it. Don't conflate them.
- Say **"bundle"**, not "dictionary", for the output format.
- Use **"Variant"/"Variation"** in headers; introduce Cat-VRS types only in a GKS/GKM representation context.

## Roadmap page

`docs/reference/roadmap.md` has an **auto-generated** table between `<!-- ROADMAP:START -->` /
`<!-- ROADMAP:END -->` — do **not** hand-edit that region. It is produced by `src/scripts/generate-roadmap.py`
from GitHub Discussions labeled **`roadmap authorized`** (ordered by built-in upvotes) and regenerated by the
deploy workflow on discussion events + a daily schedule. To add/remove a roadmap item, add/remove the label on
its discussion (Ideas category); to change status, use a `status: <x>` label. See
[ADR 0003](decisions/0003-roadmap-from-labeled-discussions.md).
