Working in Python¶

ClinVar-GKM records are GA4GH objects, so the GA4GH Python reference implementations read them directly: vrs-python (ga4gh.vrs), cat-vrs-python (ga4gh.cat_vrs) and va-spec-python (ga4gh.va_spec), collected with other tools in the GKM Starter Kit. This page loads records from a bundle and from Parquet, follows their #/section/id pointers, builds the libraries' pydantic models from them, and serializes the models back to JSON.

It assumes the bundle layout described in Output Format and ID References, and, for the Parquet section, the data column described in The 22 Tables.

Tested with

Every code block on this page was run on 2026-10-22, with Python 3.12, against 1.1.0 data: the sample bundle, the 2026-10-18 weekly delta, and the Parquet dataset built from 2026-10-18. Versions: ga4gh.vrs 2.4.0a6, ga4gh.cat_vrs 0.8.0a6, ga4gh.va_spec 0.5.0a7, ga4gh.gkm 0.4.1, pydantic 2.14.1, duckdb 2.0.0, ijson 3.6.0, and the ClinVar-GKM schema tree at tag 1.1.0.

Install¶

ClinVar-GKM 1.1.0 is written to VRS 2.1.1, Cat-VRS 1.1.1, VA-Spec 1.1.0 and GKM-Core 1.3.0. The library releases that implement exactly those versions are, as of this writing, pre-releases:

Get the example files¶

The examples use two small files:

  • nch-igm-bundle.json.gz (1.6 MB): a self-contained 1.1.0 sub-bundle of every SCV from one submitter (IGM Clinical Laboratory, Nationwide Children's Hospital) and everything those SCVs reference, cut from the 2026-10-18 release with Sub-Bundle Extraction. Every pointer in it resolves inside the file.
  • clinvar-gkm-delta_2026-1018.json.gz (24 MB): the published 2026-10-18 weekly delta.
curl -sLO https://github.com/clingen-data-model/clinvar-gkm/raw/main/nch-igm-bundle.json.gz
curl -sO https://data.clinvar-gkm.org/v1/1.1/deltas/clinvar-gkm-delta_2026-1018.json.gz

The full bundles are about 4.8 GB compressed. Don't json.load one; see Large bundles.

Load a bundle and follow pointers¶

A bundle is one JSON object whose sections map an id to a record. json.load is enough to read one:

import gzip
import json

with gzip.open("nch-igm-bundle.json.gz", "rt") as f:
    bundle = json.load(f)

print(bundle["schema_version"])
print({section: len(records) for section, records in bundle.items() if isinstance(records, dict)})


def resolve(pointer):
    """Return the record that a '#/section/id' pointer names."""
    section, key = pointer.removeprefix("#/").split("/", 1)
    return bundle[section][key]

A delta is not self-contained

A weekly delta carries only the records that changed, so its pointers can name records that are only in the full bundle it applies to. The 2026-10-18 delta, for example, has no sequenceReference section. Resolve a delta's pointers against the full bundle after applying the delta.

Into the GA4GH models¶

Each section's records, except the ClinVar custom propositions, validate as one class from the libraries. A pointer string is accepted wherever a field allows a reference: the models type it as iriReference, and its .root holds the pointer.

VRS alleles and their identifiers¶

from ga4gh.core import ga4gh_identify
from ga4gh.vrs import models as vrs

vrs_allele = vrs.Allele(**allele)
print(type(vrs_allele.location).__name__, vrs_allele.location.root)


def content(record):
    """A record without its stored identifiers."""
    return {k: v for k, v in record.items() if k not in ("id", "digest")}


# Recompute the VRS identifier from content alone: inline the location and its sequence reference
fresh = vrs.Allele(**content(allele) | {"location": content(location) | {"sequenceReference": sequence}})
print(ga4gh_identify(fresh), ga4gh_identify(fresh) == allele["id"])

iriReference #/location/ga4gh:SL.sk5GccwF1vh_M4zGnjDYkoYNGrRKc6uW

ga4gh_identify needs the location inline: the allele's digest is computed over its location's digest, and the location's over its sequence reference. Recomputed this way, all 2,027 allele ids and the one copyNumberChange id in the sample match the published ids.

Cat-VRS categorical variants¶

A variation record is a Cat-VRS CategoricalVariant. Its defining constraint points to an allele (or, for copy-number variants, a location) record:

print([relation.primaryCoding.code.root for relation in constraint.relations])
print({e.name: e.value for e in categorical.extensions if isinstance(e.value, str)})

Records in the scv, vcv and rcv sections load as Statement, and evidenceLine records as EvidenceLine. The ClinVar-GKM statement profiles (ClinvarScvStatement, ClinvarVcvStatement, ClinvarRcvStatement) add no top-level fields to VA-Spec's Statement; their ClinVar-specific content is in extensions.

Extensions and ClinVar-specific types¶

  • Extensions load as GKM-Core Extension objects. name is a string; value keeps whatever JSON the record holds, including the structured values such as submittedCondition and clinvarHgvsList. The libraries don't interpret them. Statement extensions and Variations document each one.
  • ClinVar custom propositions have no class in va-spec-python yet. The propositionClinvarCustom section holds ClinVar's own germline proposition types (ClinvarOtherProposition, ClinvarRiskFactorProposition, …). Work with them as plain JSON, as the bundle and the Parquet data column provide them. Every other section loads into a library class without loss; see Round trip.

The GKM Toolkit¶

The GKM Toolkit (ga4gh.gkm) validates a producer's bundle against that producer's schemas. That is its intended way to validate producer data: you supply the schemas, and it checks every record against them. Validation works on ClinVar-GKM 1.1.0 bundles today; the toolkit's loader does not yet read them (see Loading bundles).

Validate a bundle¶

The 1.1.0 release was validated this way: validate_bundle_schema with a validator= whose referencing registry holds the ClinVar-GKM 1.1.0 schemas and the GA4GH schemas they reference, taken from the schema/ tree of this repository at tag 1.1.0. Release Validation lists the results, and its verification reports record, per published file, the schemas and tool versions used.

Get the schema tree. The GA4GH schemas come in through the va-spec submodule:

git clone -q --depth 1 --branch 1.1.0 --recurse-submodules --shallow-submodules \
    https://github.com/clingen-data-model/clinvar-gkm.git clinvar-gkm-1.1.0

Register every schema in the tree by its $id, then validate:

import os
from collections import Counter
from pathlib import Path

from jsonschema import Draft202012Validator
from referencing import Registry, Resource
from ga4gh.gkm.bundles import BundleValidationError
from ga4gh.gkm.bundles.schema_validation import validate_bundle_schema

# Every schema in the 1.1.0 tree, keyed by $id: ClinVar-GKM's own and the GA4GH schemas they reference
schemas = {}
for directory, _, files in os.walk("clinvar-gkm-1.1.0/schema", followlinks=True):
    for name in files:
        try:
            document = json.loads(Path(directory, name).read_text())
        except (ValueError, UnicodeDecodeError):
            continue  # Makefiles and YAML sources
        if isinstance(document, dict) and "$id" in document:
            schemas[document["$id"]] = Resource.from_contents(document)
print(sorted(Counter("/".join(uri.split("/")[5:7]) for uri in schemas).items()))

bundle_schema = json.loads(Path("clinvar-gkm-1.1.0/schema/clinvar-gkm/clinvar-gkm-bundle.schema.json").read_text())
validator = Draft202012Validator(bundle_schema, registry=Registry().with_resources(schemas.items()))

validate_bundle_schema(bundle, bundle_schema, validator=validator)  # raises BundleValidationError on a violation
print("valid:", sum(len(records) for records in bundle.values() if isinstance(records, dict)), "records")

broken = json.loads(json.dumps({"schema_version": "1.1.0", "scv": {scv["id"]: scv}}))
broken["scv"][scv["id"]]["direction"] = "sideways"  # not a VA-Spec direction
try:
    validate_bundle_schema(broken, bundle_schema, validator=validator)
except BundleValidationError as error:
    print(error)

[('cat-vrs/1.1.1', 16), ('clinvar-gkm/1.1.0', 28), ('gkm-core/1.3.0', 11), ('va-spec/1.1.0', 40), ('vrs/2.1.1', 26)]
valid: 14761 records

Records are validated as published, #/… pointers included, against the full ClinVar-GKM profiles. The whole sample, 14,761 records, took about 2 minutes on one core; variation records are the slowest.

The same schemas resolve by $id through w3id.org, so a registry can fetch them on demand instead of reading a local tree. The bundle schema itself still comes from the tree (or GitHub), because its own $id does not resolve. Fetching makes one request per schema, so validate a slice, here the first 25 records of each section:

import functools

import requests


@functools.cache
def fetch(uri):
    return Resource.from_contents(requests.get(uri, timeout=30).json())


fetching = Draft202012Validator(bundle_schema, registry=Registry(retrieve=fetch))
part = {"schema_version": bundle["schema_version"]} | {
    section: dict(list(records.items())[:25]) for section, records in bundle.items() if isinstance(records, dict)
}
validate_bundle_schema(part, bundle_schema, validator=fetching)
print("valid:", sum(len(records) for records in part.values() if isinstance(records, dict)), "records;",
      fetch.cache_info().currsize, "schemas fetched")

valid: 279 records; 74 schemas fetched

validate_bundle_schema takes a whole bundle in memory. For multi-GB full bundles, the release used a streaming, multi-process wrapper around it; that wrapper is proposed for the toolkit, as gkm-validate-bundle, in ga4gh/gkm-starter-kit#128, which is not yet released.

Loading bundles¶

The toolkit's loader needs upstream updates for ClinVar-GKM 1.1.0

The toolkit's loader tools (load_bundle, Bundle.resolve, Bundle.export and its model conversion) do not yet read ClinVar-GKM 1.1.0 bundles. They need updating upstream in two ways:

  1. The most recent GKM spec versions, which 1.1.0 data uses: GKM-Core 1.3.0, VRS 2.1.1, Cat-VRS 1.1.1 and VA-Spec 1.1.0. ga4gh.gkm 0.4.1 matches these only through the pre-release libraries above, and it accepts a schema version only when it equals the installed library's.
  2. A way to handle producer-specific classes outside VA-Spec. The loader resolves schema references only against the GA4GH schemas it ships, cannot be given a producer's schemas, and converts records only to GA4GH model classes. ClinVar-GKM extends them in schema/clinvar-gkm/: the ten custom propositions (ClinvarAffectsProposition … ClinvarUndefinedProposition), ClinvarGeneContextQualifier, the statement profiles ClinvarScvStatement, ClinvarVcvStatement and ClinvarRcvStatement, the variant profile ClinvarCategoricalVariant (with ClinvarCanonicalAllele, ClinvarCategoricalCnvChange, ClinvarCategoricalCnvCount and ClinvarNonConstrainedVariant) and ClinvarSomaticEvidenceLine. load_bundle stops at the first of these references.

Until then, use the model libraries for the standard classes and plain JSON for the extended ones, as on this page. Related work: ga4gh/gkm-starter-kit#128.

From Parquet¶

Every Parquet table has a data column holding each record's complete JSON as a string, exactly as in the bundle, so json.loads(data) gives the same record the bundle does. Read a few rows remotely with DuckDB, and build the models:

import duckdb

P = "https://data.clinvar-gkm.org/v1/1.1/parquet"

rows = duckdb.sql(f"SELECT id, location_id, data FROM '{P}/allele.parquet' LIMIT 3").fetchall()
for allele_id, location_id, data in rows:
    print(allele_id, vrs.Allele(**json.loads(data)).name)

Inside data, references are bundle pointers; the typed columns carry the bare id (location_id). Follow a reference by looking the id up in the table its prefix names (see Ids tell you where to look). Here, the alleles' locations and sequence references, and the same identifier check as above:

def by_id(table, ids, columns="id, data"):
    """Fetch the rows of one table whose id is in ids, keyed by id."""
    marks = ", ".join("?" * len(ids))
    query = f"SELECT {columns} FROM '{P}/{table}.parquet' WHERE id IN ({marks})"
    return {row[0]: row[1:] for row in duckdb.execute(query, list(ids)).fetchall()}


locations = by_id("location", [location_id for _, location_id, _ in rows], "id, sequence_reference_id, data")
sequences = by_id("sequenceReference", [sequence_id for sequence_id, _ in locations.values()])

for allele_id, location_id, data in rows:
    sequence_id, location_data = locations[location_id]
    inline = content(json.loads(location_data)) | {"sequenceReference": json.loads(sequences[sequence_id][0])}
    recomputed = ga4gh_identify(vrs.Allele(**content(json.loads(data)) | {"location": inline}))
    print(allele_id, recomputed == allele_id)

Remote reads of big tables are slow

The files are not sorted by id, so a filter reads the filtered column from every row group, one HTTP request each. On 2026-10-22, a LIMIT 3 read of a large table took 10–25 seconds, an id lookup in location 10–20 seconds, and the proposition → statement → variant lookup above 40–125 seconds in all. The CDN allows 250 requests per 10 seconds per client. For anything beyond a handful of lookups, download the tables you need and query them locally (Working at Scale).

Round trip¶

model_dump(mode="json", exclude_none=True) serializes a model back to JSON. Records carry no null fields (except the open bound of a VRS Range, which survives), so exclude_none=True loses nothing. Compare every record of the sample bundle with its round trip:

from collections import Counter

from ga4gh.core.models import MappableConcept

MODELS = {
    "sequenceReference": vrs.SequenceReference, "location": vrs.SequenceLocation, "allele": vrs.Allele,
    "copyNumberCount": vrs.CopyNumberCount, "copyNumberChange": vrs.CopyNumberChange,
    "gene": MappableConcept, "condition": MappableConcept, "therapy": MappableConcept,
    "conditionSet": va.ConditionSet, "therapyGroup": va.TherapyGroup, "submitter": va.Agent,
    "variation": catvrs.CategoricalVariant, "evidenceLine": va.EvidenceLine,
    "scv": va.Statement, "vcv": va.Statement, "rcv": va.Statement,
}


def model_for(section, record):
    if section.startswith("proposition"):
        return getattr(va, record["type"])
    return MODELS[section]


tally = Counter()
for section, records in bundle.items():
    if isinstance(records, dict) and section != "propositionClinvarCustom":  # plain JSON, no library class
        for record in records.values():
            dumped = model_for(section, record)(**record).model_dump(mode="json", exclude_none=True)
            tally[section, "identical" if dumped == record else "differs"] += 1
for (section, result), n in tally.items():
    print(f"{section:33} {result:9} {n:5}")

print(scv["contributions"][0]["date"], "->", dumped["contributions"][0]["date"])

    2019-01-22 -> 2019-01-22T00:00:00

    Every SCV has contribution dates, so every SCV differs in those fields only. Compare dates by their first ten characters, or restore them after dumping.

The same sweep over the 2026-10-18 delta (215,170 records, including vcv and rcv) gives the same result: all 18,138 SCVs differ only in contribution dates, and every other record, apart from the plain-JSON custom propositions, is identical.

Key order is not preserved: the models write fields in class-definition order. Compare parsed objects, not strings.

Large bundles¶

A full bundle is about 4.8 GB compressed, and a json.load of one does not fit in 16 GB of memory. Three ways to work with it:

  • Stream it. ijson reads one record at a time; kvitems(f, "scv") yields each (id, record) of a section. Build a model per record, keep what you need, and memory stays flat. One pass reads the whole file.
  • Query the Parquet for the latest release, and fetch the data of just the records you need, as above.
  • Cut a sub-bundle. The Sub-Bundle Extraction tool, which made the sample above, extracts a self-contained bundle for a list of statements. It reads the project's BigQuery tables, not a published file, so it needs access to those datasets.

Streaming the delta's scv section, for example, to count classifications:

import ijson

classifications = Counter()
with gzip.open("clinvar-gkm-delta_2026-1018.json.gz", "rb") as f:
    for scv_id, record in ijson.kvitems(f, "scv", use_float=True):
        classifications[va.Statement(**record).classification.name] += 1
print(sum(classifications.values()), classifications.most_common(4))

18138 [('Uncertain significance', 9724), ('Likely benign', 2766), ('Likely pathogenic', 2482), ('Pathogenic', 2337)]

use_float=True makes ijson return floats instead of Decimal.
