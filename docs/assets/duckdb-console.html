Live query console

DuckDB-Wasm · no install

Runs SQL in your browser against the published ClinVar-GKM Parquet tables over data.clinvar-gkm.org — nothing is downloaded to disk and no server runs the query. Best for exploration: counts, schema, single-table and targeted lookups return in about a second. Full scans over the big tables are slow over the network and may rate-limit; for those, download and query locally.

source:
idle

How it works. The DuckDB engine (~35 MB WASM, served from this site) loads on your first Run and is cached by your browser afterwards. It reads Parquet with HTTP range requests, so count(*) and DESCRIBE fetch only the file footer. {BASE} in a query is replaced with the selected release path. The Release list is read from the live index.json when the page opens and defaults to the newest dated monthly release, which the CDN caches; 00-latest always points at the newest release but bypasses the cache. The connection runs with SET threads=1 to stay gentle on the CDN; a parallel full scan of a big table can trip rate limiting (HTTP 429); joins across the big tables belong on your machine, materialized once. To keep load on the shared service light, the console runs at most one query every 10 seconds — the Run button greys out and a countdown beside it shows when the next query is available. Multiple statements separated by ; run in order and the last result is shown. Output is capped at 500 rows.
