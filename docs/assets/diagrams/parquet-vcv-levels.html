Reading a variant's statements

1 · The statement id decodes all three axes

Read the suffix left to right. Each segment answers a different question and points at the field that carries it.

The classification code is the proposition type, abbreviated. Each code is a shorthand enumeration of one proposition type — including the custom ones. The mapping is 1:1 and deterministic:

Query — decode a variant's statement ids, with proposition type, quality, and classification 
-- the axes fall out of the id; join the proposition for its type, read quality + classification
WITH prop AS (                    -- the four proposition tables share one schema
    SELECT id, type FROM read_parquet('proposition*.parquet')
)
SELECT regexp_extract(v.id, '-([GS])-', 1)                                      AS lane,
       regexp_extract(v.id, '-[GS]-([A-Z]+)', 1)                                AS class_code,
       coalesce(nullif(regexp_extract(v.id,'-[GS]-[A-Z]+-?(.*)$',1),''),'root') AS level,
       p.type                AS proposition_type,
       v.quality.name        AS quality,
       v.classification.name AS classification
FROM 'vcv.parquet' v
LEFT JOIN prop p ON p.id = v.proposition_id
WHERE v.id LIKE 'VCV000012871.%' ORDER BY level;

2 · Two lanes — and the extra layer under Somatic

99.9 % of statements are germline, and germline is direct: variant → proposition → statement. Somatic is tiny (0.09 %) but one somatic kind — clinical impact (SCI) — has an extra layer worth knowing.

Somatic clinical impact (SCI) has a parent claim plus specific-impact evidence lines. The SCI statement's own proposition is a VariantClinicalSignificanceProposition (the general "has clinical significance" claim). Each of its evidence lines — the shared-PK evidenceLine table (ClinvarSomaticEvidenceLine) — carries a target_proposition_id pointing at the specific impact (therapeutic response / diagnostic / prognostic), and an evidenceOutcome holding the AMP/ASCO/CAP tier (Level A/B = Tier I, Level C/D = Tier II; the -T1/-T2 in the id).

Query — a somatic clinical-impact statement's specific impacts and tiers 
-- every SCI evidence line, its specific-impact target proposition, and its tier
SELECT tp.type AS evidence_target_proposition, tp.predicate,
       e.evidenceOutcome.name AS tier, count(*) n
FROM 'evidenceLine.parquet' e
JOIN 'propositionSomaticClinicalImpact.parquet' tp ON tp.id = e.target_proposition_id
GROUP BY 1, 2, 3 ORDER BY n DESC;

3 · Aggregate levels — the highest present contributes

Within one lane + classification, the VCV is a small tree: a root carries the overall call, and its children split the submissions by level. The aggregate adopts the classification of the highest level present — so which level contributes is relative to the variant, not a fixed set. Level ← scv.quality.name.

PG and EP co-contribute. When a variant carries both a practice-guideline and an expert-panel submission (23 variants do), both are retained and contribute — the practice guideline is higher quality but does not mask or override the expert panel. The strict highest-present-wins masking applies below them: CP over NOCP over NOCL.

Query — rank submissions by review level (the aggregate adopts the highest present) 
-- scv.quality.name IS the level; rank it to find each aggregate's contributing tier
SELECT s.quality.name AS review_status,
  CASE s.quality.name
    WHEN 'practice guidelines'            THEN 5  WHEN 'expert panel' THEN 4
    WHEN 'criteria provided'              THEN 3  WHEN 'no assertion criteria provided' THEN 2
    WHEN 'no classification'              THEN 1  ELSE 0 END AS precedence,
  count(*) n
FROM 'scv.parquet' s GROUP BY 1, 2 ORDER BY precedence DESC;
