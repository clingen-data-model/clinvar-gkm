**Title:** ClinVar-GKM 1.1.0 on `<CUTOVER DATE>`: proposition sections reorganized, every published file
rewritten

**Body:**

On **`<CUTOVER DATE>`** we will publish ClinVar-GKM **1.1.0**. It is a **breaking** release. It replaces every
published file under `/v1/` in place: the 4 monthly full bundles, `00-latest`, the 15 weekly deltas and every
Parquet set. We are still before GA, so under our versioning policy (ADR 0004 §5) this ships in place, with
no parallel 1.0.x line. ADR 0006 records why.

### What changes

**Propositions are grouped by meaning, not by the shape of their object.** Four new bundle sections and
Parquet tables replace the old four. Proposition ids don't change; only the section does.

| Proposition type (id code) | Old section / table | New section / table |
| --- | --- | --- |
| `VariantPathogenicityProposition` (`PATH`) | `varcond-proposition` | `propositionPathogenicity` |
| `VariantClinicalSignificanceProposition` (`SCI`) | `varcond-proposition` | `propositionSomaticClinicalImpact` |
| `VariantDiagnosticProposition` (`DIAG`) | `varcond-proposition` | `propositionSomaticClinicalImpact` |
| `VariantPrognosticProposition` (`PROG`) | `varcond-proposition` | `propositionSomaticClinicalImpact` |
| `VariantTherapeuticResponseProposition` (`TR`) | `vartherapy-proposition` | `propositionSomaticClinicalImpact` |
| `VariantOncogenicityProposition` (`ONCO`) | `vartumor-proposition` | `propositionOncogenicity` |
| the 9 `Clinvar*` types and `ClinvarUndefinedProposition` (`NP`, `DR`, `OTH`, `RF`, `ASSOC`, `AFF`, `CDFS`, `PROTECT`, `CS`, `UNDEF`) | `varcustom-proposition` | `propositionClinvarCustom` |

**Every statement and evidence-line pointer changes** to name the new section:
`#/varcond-proposition/SCV001234567-PATH` becomes `#/propositionPathogenicity/SCV001234567-PATH`. Code that
resolves pointers generically (`#/<section>/<id>`) needs no change.

**The four proposition Parquet tables share one column schema**, so `read_parquet('proposition*.parquet')`
reads them all with no renaming. Every table has every column, and a column that doesn't apply is NULL:

| Old table.column | New column |
| --- | --- |
| `varcond-proposition.object_condition_id` | `object_id` |
| `vartumor-proposition.object_tumor_type_id` | `object_id` |
| `vartherapy-proposition.object_therapy` | `object_id` |
| `varcustom-proposition.subject_id` | `subject_variant_id` |
| `varcustom-proposition.object_id` | `object_id` |
| `vartherapy-proposition.condition_qualifier_id` | `condition_qualifier_id` (now on every table) |
| — | `object_type` (new: `condition`, `conditionSet`, `therapy` or `therapyGroup`) |
| `mode_of_inheritance`, `penetrance` (varcond, varcustom only) | on every table |

**Versions:** the schema `$id`s move to `https://w3id.org/clingen/schema/clinvar-gkm/1.1.0/…`, and every
bundle declares `"schema_version": "1.1.0"`.

**Every published file is rewritten in place.** The 4 monthly fulls (2026-07 … 2026-10), `00-latest`, the 15
deltas (2026-07-06 … 2026-10-11) and every Parquet set are rebuilt and re-uploaded, and the old
`var*-proposition.parquet` files are deleted. Contents and checksums change. After the cutover R2 serves only
the new layout.

### Fixes in the same release

These ride the same rebuild, so every published file gets them too:

- **Variant schema:** the four `ClinvarCategoricalVariant` branches are mutually exclusive, and the bundle
  validates `variation` through it. No valid record is rejected.
- **HGVS:** 14 variants (16 expressions) no longer carry the invalid syntax `hgvs.?`. ClinVar's text is kept as
  an extension.
- **Duplicate allele keys:** each allele has exactly one `allele` record.
- **RCV propositions without an object:** the 4 propositions of `RCV000001117` have their condition again.
- **Condition references:** VCV proposition objects and the members of `vcv-` condition sets are `#/` pointers,
  like every other reference.
- **Citations:** one Document per ClinVar citation. URL-only and text-only citations are restored, and DOIs
  are repaired, with the originals kept as extensions.
- **Gene context:** a `geneContextSource` extension on every SCV gene-context qualifier; placeholder qualifiers
  are named with the submitter's symbol.
- **Parquet:** bare ids in the typed id columns; new typed columns on `condition`, `therapy` and
  `therapyGroup`; `gene_context_id`, `submitted_gene_symbols` and `gene_context_source` on the proposition
  tables; range bounds on `location`. Every Parquet value can be recomputed from the bundle.

The [Changelog](../../reference/changelog.md) has the details and counts once 1.1.0 is out.

### How to prepare

- **To keep the old layout**, download the files you need **before `<CUTOVER DATE>`**. There is no 1.0.x line
  after the cutover. Your copies keep working, and the `1.0.1` schemas stay resolvable at their `$id`s.
- **To tell the layouts apart**, read the bundle's `schema_version` (`1.0.1` before, `1.1.0` after) or look for
  a `propositionPathogenicity` key or file.
- **Bundle code:** read the proposition sections by prefix (every section whose name starts with
  `proposition`). To migrate stored pointers, swap the section name using the table above, keyed by the
  target record's `type`.
- **Parquet code:** replace per-table reads and `UNION ALL`s with `read_parquet('proposition*.parquet')`, and
  rename the columns as above. Earlier local copies can be read in the new shape: each old row's `data` column
  holds the full record, so the new columns can be derived from it. The Query the Data pages show how.
- **Validation:** validate against the 1.1.0 schemas
  (`https://w3id.org/clingen/schema/clinvar-gkm/1.1.0/clinvar-gkm-bundle.schema.json`).
- **Mirrors and caches:** pause any job that mirrors `/v1/` between `<CUTOVER DATE>` and the completion notice,
  then re-sync everything. Don't merge files fetched before and after the cutover.
- **Weekly releases:** no new weekly release is published between `<FREEZE DATE>` and the cutover. Weekly
  releases resume on the 1.1.0 layout.

Questions or concerns: reply here before `<CUTOVER DATE>`.
