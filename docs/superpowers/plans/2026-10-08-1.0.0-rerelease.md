**Goal:** Re-cut and republish the **1.0.0** release with (a) the 5 open docs/schema PRs merged, (b) the
`submittedCondition`/`submittedConditionSet` CURIE de-pointer (the only bundle-*data* change), and (c) the
ADR-0004 versioning infrastructure (`/v1/` layout + root manifest + bundle `schema_version` + feed) — rebuilt
across the release history via a **targeted scv-only re-run**, then re-extract the examples and close #115.

**Architecture:** Stays schema `$id` 1.0.0 (stabilization re-cut, same version string — no 2.0.0, no parallel
line). The de-pointer is content-only; the consumer re-wrap keeps `proposition.object` byte-identical so the
*only* changed bundle section is `scv`. Rebuild reuses existing variation-identity + vrsify output
(`run-release.sh --start-step 4`), re-running only the gkm proc layer + export per historical release, in
chronological order, oracle-gated.

**Tech Stack:** BigQuery dynamic-SQL procs, bash 3.2 orchestration (`run-release.sh`/`release-gkm*.sh`),
ga4gh.gkm metaschema (`make`/`y2md`), Zensical docs, Cloudflare R2, `extract-example.py`, `gh`/`git`.

**Git invariants (CLAUDE.md):** work on branches, land via PR into `1.0`; conventional commit messages with
**no** "Generated with Claude Code" / "Co-Authored-By: Claude" lines. After the release, `main` (dev) must
include the changes but keep its version string as **"dev"** (never the release tag) — see
`project_release_branch_dev_sync_policy`.

**Starting git state (2026-10-08):** `main`=`cce301d`=`1.0.0` tag; `1.0`=`cce301d`+`072207e`;
`chore/refresh-examples-jsonc`=`1.0`+3 extractor commits + uncommitted policy/plan work. Stray untracked test
bundles at repo root (`SCV004101425…`, `VCV000017662…`, `VCV000133206…`) are **not** to be committed.

**Live-R2 gate:** every R2 write (Phase 5) is a separately **user-confirmed** step; use `--dry-run` for all
dress rehearsals. Nothing before Phase 5 touches R2.
