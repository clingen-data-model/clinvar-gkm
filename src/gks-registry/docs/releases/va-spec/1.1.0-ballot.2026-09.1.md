# va-spec 1.1.0-ballot.2026-09.1

> Released: 2026-09-16

## Release Notes

## What's Changed

Version 1.1.0 consolidates the core `EvidenceLine` class into `Statement`: a "discrete evidence-based argument" is now a Statement referenced through another Statement's `hasEvidenceLines`. It also has `Proposition`/`StudyResult` subclasses narrow `subject`/`predicate`/`object`/`focus` in place instead of renaming them per subclass. It restructures the domain entities around GKM Core's `MappableConcept`/`ConceptSet` (`Therapeutic` is renamed `Therapy`) and renames the abstract `ClinicalVariantProposition`. The release also adds several *draft* propositions, substantially revises the *draft* AAC-2017, ACMG-2015, and CCV-2022 community profiles, modernizes the schema-generation pipeline, and refreshes the imported dependencies to the 2026-09 ballot line.

Changes are categorized per the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy, based on the `maturity` of each class touched, and compared against the last full release, **1.0.1**. See the [release log](https://va-spec.ga4gh.org/en/1.1.0-ballot.2026-09/releases/1.1.html) for full detail.

### Minor Version Increment
Backwards-incompatible changes and additions to *trial use* classes:
* **Evidence Line consolidated into Statement.** `EvidenceLine` is removed.
  * `Statement` gains `hasEvidenceItems`, and its `hasEvidenceLines` now holds `Statement | iriReference` (was `EvidenceLine | iriReference`).
  * `EvidenceLine`'s attributes move onto `Statement`: `targetProposition` → `proposition`, which is now optional; `directionOfEvidenceProvided` → `direction`; `strengthOfEvidenceProvided` → `strength`; `evidenceOutcome` and Statement's `classification` merge into `outcome`; `qualityOfEvidenceProvided` → `quality`.
* **Subject / object / focus.** `Proposition` declares `subject`/`predicate`/`object` and `StudyResult` declares `focus`, and every subclass narrows them in place: `subjectVariant` → `subject`; `objectCondition`/`objectTumorType`/`objectSequenceFeature`/`objectTherapeutic` → `object`; `focusAllele`/`focusVariant` → `focus`. The abstract `Proposition`, `StudyResult`, and `SubjectVariantProposition` bases are now open, so implementers can define their own subclasses.
* **Domain entities restructured.**
  * `Therapeutic` is renamed `Therapy`.
  * `Condition` and `Therapy` are now single `MappableConcept` specializations, and the single-or-set union moves to where they're used (e.g. `object`: `Condition | ConditionSet | iriReference`).
  * `ConditionSet` and `TherapyGroup` now specialize `ConceptSet`, with `conditions`/`therapies` renamed `concepts`.
* **Adopts GKM Core 1.2.0 `MappableConcept`/`ConceptSet`.** Both now require a `type` discriminator, which propagates to `Condition`, `Therapy`, `ConditionSet`, and `TherapyGroup`.
* **Adopts GKM Core 1.3.0.** `ConditionSet` and `TherapyGroup` now accept the optional `conceptSetType`.
* **Renames** `ClinicalVariantProposition` → `GeneticContextVariantProposition`.
* **Renames** `CohortAlleleFrequencyStudyResult` `focusAlleleCount` → `focusCount`, `locusAlleleCount` → `locusCount`, and `focusAlleleFrequency` → `alleleFrequency`.
* **Allows an `iriReference`** in place of an inline object on attributes that reference independently-identifiable entities. Examples: `Contribution.contributor`, `Statement.proposition`/`.strength`/`.outcome`/`.quality`, `StudyResult.sourceDataSet`, and `VariantPathogenicityProposition`'s qualifiers.

### Patch Version Increment
New *draft* features, changes to *draft* classes, and supporting changes:
* adds `GeneDiseaseValidityProposition`, `VariantMolecularConsequenceProposition`, `VariantClinicalSignificanceProposition`, and `DataItem` (all *draft*).
* revises the *draft* community profiles:
  * AAC-2017: `AmpAscoCapStatement` and its `Diagnostic`/`Prognostic`/`TherapeuticStatement` subclasses.
  * ACMG-2015 and CCV-2022: evidence lines and statements now compose `Statement`; `methodType` codes are normalized to `snake_case`; `no_criteria_met` outcomes are added; the `if`/`then` tier constraints are fixed; and `hasEvidenceLines` accepts IRIs.
* migrates the metaschema processor to `ga4gh.gkm.metaschema` 0.4.8 and its source conventions, and emits a JSON Schema for every abstract class.
* reorganizes `schema/va-spec/` into a flat folder using the processor's profile sub-namespace convention, and makes the docs self-contained.
* refreshes dependencies to the 2026-09 ballot line: Cat-VRS `1.1.1`, VRS `2.1.1`, and GKM Core `1.3.0` (#446).
* various documentation, example, test-fixture, and tooling updates.
