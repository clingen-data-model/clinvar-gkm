# gks-core 1.3.0-ballot.2026-09.1

> Released: 2026-09-16

## Release Notes

## What's Changed

Version 1.3.0 adds an optional `conceptSetType` to `ConceptSet`, matching the `conceptType` already on `MappableConcept`. It also moves GKM Core to the renamed `ga4gh.gkm.metaschema` processor and its abstract-class convention. `Entity` and `Element` are now declared `abstract: true` and published as standalone, open JSON Schemas, so downstream specifications (VRS, Cat-VRS, VA-Spec) can reference these root classes directly. The concrete classes stay closed to undefined properties, so existing valid 1.2.0 instances still validate.

Changes are categorized per the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy, based on the `maturity` of each class touched. All GKM Core classes are currently at **trial use**.

### Minor Version Increment
* adds the optional `ConceptSet.conceptSetType` property, which names the kind of concept a `ConceptSet` represents. This adds an optional field to a trial-use class. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138

### Patch Version Increment
* adopts the renamed `ga4gh.gkm.metaschema` processor (formerly `ga4gh.gks.metaschema`), pinned to the published `0.4.8` release, and its abstract-class convention. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
  * `Entity` and `Element` are marked `abstract: true`; `heritableProperties`/`heritableRequired` become `properties`/`required`.
  * `Entity` and `Element` are now emitted as standalone JSON Schema files (`json/Entity`, `json/Element`). They are left open, with no `additionalProperties`/`unevaluatedProperties` closure.
  * concrete classes are closed by the processor. `MappableConcept` now closes with `unevaluatedProperties: false` instead of `additionalProperties: false`; the instances it accepts are unchanged.
* the generated JSON Schema no longer carries `$comment` annotations. They remain in the source YAML and the generated `def/` docs. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
* fixes the `datetime` description's format string (`YYYY:MM::DD...` → `YYYY-MM-DD...`). The `format: date-time` constraint is unchanged. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
* adds a negative-example test harness (`examples/invalid/`, `tests/test_invalid_definitions.yaml`), valid examples for the previously untested `ConceptMapping`, `ConceptSet`, and `Extension` classes, and schema-invariant tests that check the abstract-open / concrete-closed convention against the generated JSON. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
* links the README to the `ga4gh/gks-metaschema` processor repo and documents the valid/invalid example layout. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
* sets the schema `$id` version token to `1.3.0-ballot.2026-09.1`. By @larrybabb in https://github.com/ga4gh/gkm-core/pull/138
