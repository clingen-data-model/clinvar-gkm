# gks-core 1.3.0

> Released: 2026-09-30

## Release Notes

GKM Core 1.3.0 extends `ConceptSet` (`trial use`) so concept sets can carry a type annotation and reference external concepts by IRI instead of only inlining them, and migrates the schema source to the GKM metaschema processor's 0.4.x abstract-class convention.

Changes below are categorized per the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy's Major/Minor/Patch versioning rules, based on the `maturity` of each class touched.

## Minor Version Increment

- Adds an optional `conceptSetType` field to `ConceptSet` (`trial use`), for annotating the kind of concept a set represents
- Adds `iriReference` as an allowed `ConceptSet.concepts` member (`trial use`), alongside `MappableConcept`/`ConceptSet`, so a concept set can reference an external concept by IRI instead of only inlining it ([`e6e5c1a`](https://github.com/ga4gh/gkm-core/commit/e6e5c1aaf11383673113088b835c2bf749c4d41a))

## Patch Version Increment

- Migrates the schema source to the GKM metaschema processor's 0.4.x abstract-class convention (`heritableProperties`/`heritableRequired` → `properties`/`required` + explicit `abstract: true`); generated JSON Schema output is unchanged in meaning
- Completes the `gks` → `gkm` rebrand in remaining README/CI references ([#141](https://github.com/ga4gh/gkm-core/pull/141))
- Adds a negative-example test harness, concrete-class coverage checks, and schema invariant tests
- Fixes a typo in the `date-time` format description (`YYYY:MM::DD` → `YYYY-MM-DD`)
- Several `ga4gh.gkm.metaschema` processor version bumps (0.4.0 → 0.4.8)

**Full Changelog**: https://github.com/ga4gh/gkm-core/compare/1.2.0...1.3.0
