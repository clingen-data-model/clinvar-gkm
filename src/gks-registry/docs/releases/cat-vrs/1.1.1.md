# cat-vrs 1.1.1

> Released: 2026-10-01

## Release Notes

Version 1.1.1 is a **patch** release that modernizes the Cat-VRS build pipeline and advances its imported dependencies (VRS `2.1.1` and GKM Core `1.3.0`). No change alters which instances validate against a **trial use** class, and there are no additions or removals to the set of Cat-VRS product features.

## Patch changes

The following **product features** at **trial use** maturity were modified without changing which instances validate:

- `Constraint`: the abstract base is now declared `sealed`. The metaschema processor renders it as a closed union of its concrete subtypes with a `type` discriminator (matching the VRS abstract-class convention). The derived union is the same seven concrete subtypes that 1.1.0 listed by hand, and every subtype already required `type`. `CategoricalVariant.constraints` now references `Constraint` directly, which resolves to the same set.
- Canonical Allele (and the **draft** Categorical CNV) recipe now declares `unevaluatedProperties: false`. Both recipes already inherited closure from `CategoricalVariant`, so the set of valid instances is unchanged.

## Dependencies

- The Cat-VRS schema identifier (`$id`) is now `https://w3id.org/ga4gh/schema/cat-vrs/1.1.1/...`.
- Imported schemas were advanced to VRS `2.1.1` and GKM Core `1.3.0`. The only data-model changes in GKM Core 1.3.0 — a new optional `ConceptSet.conceptSetType` field and `iriReference` as a new allowed `ConceptSet.concepts` member — do not reach Cat-VRS: Cat-VRS uses `MappableConcept`, which 1.3.0 leaves unchanged, but not `ConceptSet`.

## Supporting changes

The following **supporting** changes were made to Cat-VRS that do not impact the Cat-VRS data model:

- Adopted the modernized GKM metaschema processor (`ga4gh.gkm.metaschema` 0.4.8), with which the source YAMLs are compiled (`source2classes`/`source2splitjs`/`y2t`). Cross-schema references in the recipe definitions now use explicit `$refCurie` (e.g. `cat-vrs:CategoricalVariant`), as required by the stricter 0.4.x processor.
- Cat-VRS now generates and owns the documentation definitions for its imported VRS and GKM Core classes locally, rather than depending on the submodule's pre-generated definitions. Imported VRS class pages link to the full definition in the latest [VRS specification](https://vrs.ga4gh.org/en/latest/).
- Renamed the "Data Model" documentation section to "Model" (consistent with VRS) and consolidated the Constraint documentation onto a single index page.
- The pre-commit CI job now checks out submodules, matching the local hook, so schema regeneration is verified in CI.
