# cat-vrs 1.1.1-ballot.2026-09.1

> Released: 2026-09-16

## Release Notes

## What's Changed

Version 1.1.1 modernizes the Cat-VRS build pipeline and advances its imported dependencies to the 2026-09 ballot line (VRS `2.1.1`, GKM Core `1.3.0`). The abstract `Constraint` base is now declared *sealed*: the processor derives its closed set of concrete subtypes instead of relying on a hand-written `oneOf`. The derived set matches 1.1.0 exactly, so no change alters which instances validate against a trial-use class. There are no additions or removals to the set of Cat-VRS product features.

Changes are categorized per the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy, based on the `maturity` of each class touched. None of the changes alter which instances validate against a trial-use class, so all of them fall under Patch.

### Patch Version Increment
* declares the trial-use `Constraint` base `sealed`. It renders as a closed union of its concrete subtypes with a `type` discriminator, matching the VRS abstract-class convention. The derived union is the same seven subtypes 1.1.0 listed by hand, and every subtype already required `type`. `CategoricalVariant.constraints` now references `Constraint` directly, which resolves to the same set. By @larrybabb in https://github.com/ga4gh/cat-vrs/pull/261
* the `CanonicalAllele` (trial use) and `CategoricalCnv` (draft) recipes now declare `unevaluatedProperties: false`. Both already inherited closure from `CategoricalVariant`, so the set of valid instances is unchanged. By @larrybabb in https://github.com/ga4gh/cat-vrs/pull/261
* advances imported schemas to VRS `2.1.1-ballot.2026-09.1` (ga4gh/vrs#718) and GKM Core `1.3.0-ballot.2026-09.1`. GKM Core 1.3.0's only data-model change, an optional `ConceptSet.conceptSetType`, doesn't reach Cat-VRS: Cat-VRS uses `MappableConcept`, which 1.3.0 leaves unchanged, but not `ConceptSet`. By @larrybabb and @ahwagner in https://github.com/ga4gh/cat-vrs/pull/261
* sets the Cat-VRS schema identity (`$id`) to `1.1.1-ballot.2026-09.1`. By @ahwagner in https://github.com/ga4gh/cat-vrs/pull/261
* adopts the modernized GKM metaschema processor (`ga4gh.gkm.metaschema` 0.4.8). Cross-schema references in the recipe definitions now use explicit `$refCurie` (e.g. `cat-vrs:CategoricalVariant`), as the stricter 0.4.x processor requires. By @larrybabb in https://github.com/ga4gh/cat-vrs/pull/261
* generates the documentation definitions for imported VRS and GKM Core classes locally, rather than depending on the submodule's pre-generated definitions. By @larrybabb in https://github.com/ga4gh/cat-vrs/pull/261
* renames the "Data Model" documentation section to "Model" (consistent with VRS) and consolidates the `Constraint` documentation onto a single index page. By @larrybabb and @brendanreardon in https://github.com/ga4gh/cat-vrs/pull/261
* the pre-commit CI job now checks out submodules, matching the local hook. By @larrybabb in https://github.com/ga4gh/cat-vrs/pull/261
