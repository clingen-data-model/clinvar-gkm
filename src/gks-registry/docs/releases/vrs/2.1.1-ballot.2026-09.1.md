# vrs 2.1.1-ballot.2026-09.1

> Released: 2026-09-16

## Release Notes

## What's Changed

Version 2.1.1 moves VRS to the renamed GKM metaschema processor (`ga4gh.gkm.metaschema`) and its abstract-class convention, and tracks the GKM Core 1.3.0 ballot. The abstract classes `Variation`, `MolecularVariation`, `SystemicVariation`, `Location`, and `SequenceExpression` are now declared *sealed*: the processor derives each class's closed set of concrete subclasses instead of relying on hand-maintained `oneOf` lists. The derived sets match 2.1.0 exactly, so the instances VRS accepts and their computed identifiers are unchanged. This release also renames the "Concepts" documentation section to "Model", aligns the maturity model page with the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy, and substantially expands the test suite.

Changes are categorized per the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy, based on the `maturity` of each class touched. None of the changes alter which instances validate against a trial-use class, so all of them fall under Patch.

### Patch Version Increment
* adopts the renamed `ga4gh.gkm.metaschema` processor (`0.4.8`) and its abstract-class convention: abstract classes are marked `abstract: true` and left open, while concrete classes stay closed to undefined properties (`additionalProperties`/`unevaluatedProperties: false`), as they already were in 2.1.0. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* declares `Variation`, `MolecularVariation`, `SystemicVariation`, `Location`, and `SequenceExpression` `sealed: true`, replacing their hand-written `oneOf` unions with processor-derived ones. The derived unions are identical to 2.1.0's. Properties that previously inlined a `oneOf` over the sequence expression classes (`Allele.state`, `RelativeAllele.baseState`/`mappedState`, `Adjacency.linker`) now reference `SequenceExpression` instead, which resolves to the same three classes. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* publishes `Ga4ghIdentifiableObject` as a standalone, open JSON Schema (`json/Ga4ghIdentifiableObject`). By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* bumps the gkm-core submodule from `1.2.0` to `1.3.0-ballot.2026-09.1`. The only data-model change in GKM Core 1.3.0 is a new optional `ConceptSet.conceptSetType`, and no VRS class uses `ConceptSet`. VRS classes that inherit from GKM Core's `Entity` (`Ga4ghIdentifiableObject`, `SequenceExpression`, `SequenceOffsetLocation`, `TraversalBlock`) or `Element` (`Expression`) see no property changes, since 1.3.0 only marks those root classes abstract. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* retokenizes the schema identity (`$id`) to `2.1.1-ballot.2026-09.1`. By @ahwagner in https://github.com/ga4gh/vrs/pull/718
* aligns the maturity model page with the GA4GH TASC [Technical Specification Development](https://www.ga4gh.org/document/tasc-technical-specification-development/) policy. By @ahwagner in https://github.com/ga4gh/vrs/pull/714
* renames the "Concepts" documentation section to "Model", generates the imported GKM Core class definitions locally instead of linking them from the submodule, and fixes the maturity model link. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* expands the test suite with schema-invariant tests (abstract classes open, concrete classes closed), negative examples (`examples/invalid/`), concrete-class coverage for every instantiable VRS class, and `$ref` version-token resolution tests. Also regenerates the stale `validation/json/models.json`, adding the missing fixtures for the draft intronic-position classes. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* updates the pre-commit CI job to check out submodules and install the schema-build dependencies, and makes the `update-json-def-files` hook fail on a `make` error. By @larrybabb in https://github.com/ga4gh/vrs/pull/718
* references the GA4GH metaschema processor in the README and refreshes contributor guidance (`.claude/CLAUDE.md`). By @larrybabb in https://github.com/ga4gh/vrs/pull/718
